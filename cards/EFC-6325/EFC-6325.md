# EFC-6325 — [document-builder] Novo motor de geração de documentos

## 1. Contexto e Motivação

O projeto possuía um módulo legado chamado `gerador-documentos`, herdado de outro repositório e adaptado para uso local. Apesar de funcional para os documentos existentes (Ficha Individual, Ata de Resultados Finais, Lista de Presença), o módulo apresentava problemas estruturais que tornavam difícil criar novos documentos:

- **Lógica de paginação acoplada a cada documento** — cada novo documento precisava reimplementar a lógica de controle de páginas, split de componentes e medição de alturas.
- **Componentes não sabiam se dividir** — não havia contrato formal para que uma tabela, por exemplo, declarasse como quebrar entre páginas. O split era feito manualmente por cada documento.
- **`setTimeout` frágil no layout** — a fase de medição dependia de delays não-determinísticos para aguardar o DOM.
- **Nomes em português misturados com inglês**, tipos importados de outros módulos de domínio (`@models/impressao.model`, `@app/turma/model/turma.model`), sem isolamento.
- **Sem debug de layout** — impossível inspecionar distribuição de componentes por página sem `console.log`.

A inspiração para a solução veio do módulo `filtro` do mesmo projeto: um filtro é "iniciado" com uma config e monta sua UI dinamicamente, sem que o consumidor escreva lógica de layout. A premissa central do novo módulo:

> **Um documento é apenas um arquivo de configuração bem definido.**

---

## 2. Critérios de Aceitação

- Motor de layout determinístico, sem `setTimeout`, capaz de distribuir componentes entre páginas A4.
- Contratos formais (`Splittable`, `TextMeasurable`) para que componentes declarem como se dividem e medem.
- Geração de PDF via `html-to-image` + `jsPDF` com renderização paralela.
- Painel de debug ativável via config (`config.debug: true`).
- Rota de exemplos com tela de grade de documentos.
- 8 modelos de documentos escolares prontos (Histórico, Boletim, Declaração, Certificado, Ata, Plano de Aula, Relatório, Comunicado).
- README.md completo com guia de implementação.

## 4. O Que Precisa Ser Feito

O desenvolvimento foi executado em 9 tarefas sequenciais + criação de blocos genéricos e modelos escolares:

**Tarefa 01 — Estrutura base e tipagem**  
Módulo `src/shared/document-builder/` com interfaces: `DocumentConfig`, `DocumentEntry<T>`, `Splittable`, `TextMeasurable`.

**Tarefa 02 — LayoutEngine**  
`LayoutEngineService` distribui componentes entre páginas A4 sem DOM. Suporta split recursivo via `Splittable`. Coberto por 11 testes unitários.

**Tarefa 03 — Componentes base de conteúdo**  
9 componentes em inglês com `@chenglou/pretext` para medição sem DOM: `DocTitleComponent`, `DocTextFieldComponent`, `DocTextComponent`, `DocLegendComponent`, `DocHeaderComponent`, `DocFooterComponent`, `DocSignatureComponent`, `DocFrameComponent`, `DocInfoGridComponent`.

**Tarefa 04 — DocumentViewer, DocumentPage e MeasurementService**  
Pipeline de inicialização em 3 fases: Medição → Distribuição (LayoutEngine) → Renderização (move elementos via `appendChild`). Aguarda `document.fonts.ready`. Criado `PrintService` base.

**Tarefa 05 — PrintService com paralelismo e compressão**  
`Promise.allSettled` para converter páginas em paralelo. `compress: true` no jsPDF. Tratamento de erros por página.

**Tarefa 06 — DocumentDebugComponent**  
Painel sidebar (`config.debug: true`), oculto no PDF via `@media print`. Exibe espaço total/usado/livre por página e metadados por componente.

**Tarefa 07 — Rota de exemplos e TestDocBodyComponent**  
Rota `/exemplos/documents` (condicionada a `environment.useExempleModule`). `PrintOverlayComponent` com viewer integrado, botões de imprimir, salvar PDF e toggle de debug.

**Tarefa 08 — DocTableComponent com Splittable**  
`getRowHeight()` via Pretext, `split(n)` sem mutar `@Input() data`. `renderData` adicionado ao `LayoutComponent` para criar tails via `ViewContainerRef.createComponent()`. Validado com tabela de 55 linhas.

**Tarefa 09 — README.md do módulo**  
Fluxo interno, exemplo mínimo, tabela de componentes, guia de `TextMeasurable` e `Splittable`, limitações do Pretext.

**Blocos genéricos e modelos escolares**  
3 novos blocos: `DocSectionComponent`, `DocInfoRowComponent`, `DocStatementComponent`.  
8 modelos em `exemplos/documents/modelos/`.
