# Plano T8 — Simplificar `GetAvaliacoes` (FiltroManager) com colunas CF da view

> Escopo: apenas o branch `if (filtro.EscopoAvaliacoes.EhEscopoCF())` em `FiltroManager.GetAvaliacoes`.

---

## 1. Contexto

`ViewConfiguradorAvaliacao` passou a ter quatro colunas booleanas no nível de **Etapa**:

| Coluna na view             | Escopo correspondente                     |
|---------------------------|------------------------------------------|
| `EtapaDeComponenteAnual`  | `EscopoEnum.ComponenteFormativo_Anual`   |
| `EtapaDeComponenteSemestral` | `EscopoEnum.ComponenteFormativo_Semestral` |
| `EtapaDeComponenteTrimestral` | `EscopoEnum.ComponenteFormativo_Trimestral` |
| `EtapaDeComponenteBimestral` | `EscopoEnum.ComponenteFormativo_Bimestral` |

Essas colunas indicam diretamente, em cada linha da view, se a etapa daquela linha pertence a um CF do tipo correspondente.

---

## 2. Problema atual

O branch CF executa **três queries de banco** antes de filtrar a view:

```
Query 1 — estruturasCFIds
  EstruturaAvaliacaoRepository
    .Where(x => x.ItinerarioFormativoCiclo.Id == idCicloIF)
    .Select(x => x.Id)

Query 2 — estruturasAutomaticasIds
  EstruturaAvaliacaoRepository
    .Where(x => x.ItinerarioFormativoCiclo == null
             && Boletim && !Diversificada && !Simulados
             && (FaltaEtapa || Total || Media || Situacao))
    .Select(x => x.Id)

Query 3 — disciplinasCF
  ItinerarioFormativoRedeSerieDisciplinaRepository
    .Where(x => x.IFRS.IF.Ciclo.Id == idCicloIF)
```

Em seguida filtra a view com:
```csharp
.Where(x => estruturasParaFiltrarIds.Contains(x.IdEstrutura))
// + ao projetar:
EhEstruturaAutomatica = estruturasAutomaticasIds.Contains(x.IdEstrutura)
```

**Query 1 pode ser eliminada.** A coluna da view já codifica essa informação — uma linha com `EtapaDeComponenteAnual = true` pertence exatamente ao mesmo conjunto que Query 1 retorna para o ciclo Anual.

---

## 3. Abordagem simplificada

### 3.1 Eliminar Query 1 (`estruturasCFIds`)

Substituir o filtro `estruturasParaFiltrarIds.Contains(x.IdEstrutura)` por:

```csharp
// switch resolve qual coluna usar baseado no escopo
IQueryable<ViewConfiguradorAvaliacao> queryableCF;

switch (filtro.EscopoAvaliacoes)
{
    case EscopoEnum.ComponenteFormativo_Anual:
        queryableCF = baseQueryable.Where(x =>
            x.EtapaDeComponenteAnual || estruturasAutomaticasIds.Contains(x.IdEstrutura));
        break;
    case EscopoEnum.ComponenteFormativo_Semestral:
        queryableCF = baseQueryable.Where(x =>
            x.EtapaDeComponenteSemestral || estruturasAutomaticasIds.Contains(x.IdEstrutura));
        break;
    case EscopoEnum.ComponenteFormativo_Trimestral:
        queryableCF = baseQueryable.Where(x =>
            x.EtapaDeComponenteTrimestral || estruturasAutomaticasIds.Contains(x.IdEstrutura));
        break;
    default: // ComponenteFormativo_Bimestral
        queryableCF = baseQueryable.Where(x =>
            x.EtapaDeComponenteBimestral || estruturasAutomaticasIds.Contains(x.IdEstrutura));
        break;
}
```

### 3.2 Derivar `EhEstruturaAutomatica` via coluna da view

Com a Query 1 eliminada, a distinção "é automática ou é CF?" pode ser feita diretamente na projeção `.Select(...)`, sem depender de `estruturasAutomaticasIds.Contains(x.IdEstrutura)`:

```csharp
// Para escopo Anual, por exemplo:
EhEstruturaAutomatica = !x.EtapaDeComponenteAnual
// Qualquer linha que passou no filtro mas NÃO tem EtapaDeComponenteAnual = true
// só pode ter entrado pelo segundo lado do OR — ou seja, é automática.
```

> Nota: `estruturasAutomaticasIds.Contains(x.IdEstrutura)` ainda pode ser mantido como forma explícita. Mas `!x.EtapaDeComponenteXxx` é equivalente e elimina o carregamento da lista de IDs na projeção.

### 3.3 Revisar o guard

Antes:
```csharp
if (!disciplinasCF.Any() || (!estruturasCFIds.Any() && !estruturasAutomaticasIds.Any()))
    return new List<ViewConfiguradorAvaliacaoDTO>();
```

Depois (Query 1 removida, `estruturasCFIds` não existe mais):
```csharp
if (!disciplinasCF.Any())
    return new List<ViewConfiguradorAvaliacaoDTO>();
```

Justificativa: se não há disciplinas CF para o ciclo, não há o que exibir. Se não há estruturas automáticas, elas simplesmente não aparecem — não é motivo para retornar vazio.

### 3.4 `idCicloIF` ainda é necessário

`idCicloIF` continua sendo usado para a Query 3 (`disciplinasCF`). A linha:
```csharp
int idCicloIF = filtro.EscopoAvaliacoes.GetIdCicloIF();
```
permanece.

---

## 4. Comparativo before/after

| Aspecto | Antes | Depois |
|---|---|---|
| Queries em `EstruturaAvaliacaoRepository` | 2 (CF + automáticas) | 1 (só automáticas) |
| Filtro na view | `estruturasParaFiltrarIds.Contains(x.IdEstrutura)` | `x.EtapaDeComponenteXxx \|\| estruturasAutomaticasIds.Contains(x.IdEstrutura)` |
| `EhEstruturaAutomatica` | `estruturasAutomaticasIds.Contains(x.IdEstrutura)` | `!x.EtapaDeComponenteXxx` (ou manter o Contains — equivalente) |
| Guard | checa `estruturasCFIds.Any()` | só checa `disciplinasCF.Any()` |
| `idCicloIF` | usado por 2 queries | usado por 1 query |

---

## 5. Consideração: granularidade Etapa vs. EstruturaAvaliacao

A abordagem atual (Query 1) filtra no nível de `EstruturaAvaliacao` — `x.ItinerarioFormativoCiclo.Id == idCicloIF`.

As novas colunas estão no nível de **Etapa** — `etapa.EtapaDeComponenteAnual`.

Implicação: se uma etapa tiver ciclos de **dois tipos diferentes de CF** (ex.: um ciclo Anual e um ciclo Semestral ligados à mesma etapa), a coluna `EtapaDeComponenteAnual = true` traria todas as estruturas daquela etapa, não só as Anuais.

Na prática, uma etapa é configurada para um único tipo de CF, então esse cenário é improvável. Mas vale validar com uma etapa de teste antes de considerar a simplificação completa.
