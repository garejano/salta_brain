# EFC-6323 — Mapear funcionalidade própria para a seleção de componentes formativos

> **Fonte:** Jira (`gruposalta.atlassian.net`) — somente leitura. Não edite campos sincronizados diretamente aqui.  
> **Status:** Aguardando Ajuste | **Tipo:** Technology | **Prioridade:** Medium | **Última sincronização:** 2026-05-12

---

## 1. Contexto e Motivação

O Atlas possuía dois contextos funcionais distintos para Componentes Formativos — **Configuração** (cadastro e gestão) e **Seleção** (associação de alunos) — ambos controlados pela mesma funcionalidade `Configurador_Itinerario_Formativo` (426). Isso impedia que perfis diferentes tivessem acesso separado a cada operação.

Epic pai: **EFC-5972 — Itinerário Formativo**

---

## 2. Critérios de Aceitação

- **CA-01:** Usuário com apenas permissão de seleção (427) consegue acessar a tela de seleção e realizar a associação de alunos a componentes.
- **CA-02:** Usuário com apenas permissão de configuração (426) **não** tem acesso à tela de seleção.
- **CA-03:** A filtragem de escolas na tela de seleção respeita somente as escolas onde o usuário tem permissão de seleção (427), não de configuração.
- **CA-04:** Um mesmo usuário pode ter ambas as permissões e acessar as duas telas.

## 4. O Que Foi Implementado

### Backend — implementação correta ✅

| Arquivo | O que foi feito |
|---------|----------------|
| `Funcionalidade.cs` | Constante `ItinerarioFormativo_Selecao = 427` adicionada |
| `ItinerarioFormativoSelecaoController.cs` | `[RequiredAuthorization(427)]` em todos os endpoints de seleção |
| `FilterItinerarioFormativoSelecaoService.cs` | 7 métodos de filtro usando `GetEscolaIdByFuncionalidadeUsuarioAutenticado(427)` |
| `AlunoEscolaItinerarioFormativoSaveService.cs` | Save usando `GetEscolaIdByRedeFuncionalidadeUsuarioAutenticado(hashRede, 427)` |

A separação no backend está correta e os dados no banco confirmam que `UsuarioAcesso` registros com `FuncionalidadeId = 427` e `HashRede` preenchido existem (76.227 registros, 2.402 usuários).

### Frontend — implementação incompleta ❌

O `selecao-itinerario.component.ts` carrega a lista de componentes disponíveis chamando:

```typescript
// aplicarFiltro() — linha 75
componentes: this.itinerarioService.getItinerarios(request),
```

Esse método bate em **`POST /itinerarioformativo/itinerarios`** — endpoint do `ItinerarioFormativoController`, protegido por **permissão 426**. Um usuário com apenas 427 recebe 403, a lista de componentes fica vazia e a alocação é impossível.

O `ItinerarioFormativoSelecaoController` (protegido por 427) **não possui endpoint** para listar os itinerários disponíveis para seleção.

---

## 5. Causa Raiz do Bug Reportado pelo QA

> **Usuário com apenas permissão de seleção (427) consegue acessar a tela, mas não consegue fazer a alocação.**

Fluxo com 427 apenas:

1. Tela acessível — guards de rota comentados (`canActivate` desativado no routing module)
2. Filtros carregam corretamente (alunos, escolas, agrupamentos) — todos via `/selecao-itinerario/*` (427) ✅
3. `getItinerarios()` → `/itinerarioformativo/itinerarios` → retorna 403 → `componentes = []` ❌
4. Sem componentes para exibir, o usuário não consegue selecionar nem salvar

---

## 6. O Que Precisa Ser Feito

### Fix — adicionar endpoint de itinerários na controller de seleção

**Backend — `ItinerarioFormativoSelecaoController.cs`:**

```csharp
[HttpPost("itinerarios")]
public async Task<IActionResult> GetItinerariosFormativos(
    [FromServices] IItinerarioFormativoGetService service,
    [FromBody] ItinerarioFormativoFilterRequest request)
{
    return Result(await service.GetItinerariosFormativos(request));
}
```

> O serviço `IItinerarioFormativoGetService.GetItinerariosFormativos` pode ser reaproveitado sem alteração — ele não verifica permissão internamente; quem protege é o controller.

**Frontend — `selecao-itinerario.service.ts`:**

```typescript
getItinerarios(filter: ItinerarioFormativoSelecaoFilterRequest): Observable<ServiceResult<ItinerarioFormativoResponse[]>> {
  return this.apiClient
    .post("/selecao-itinerario/itinerarios", filter)
    .pipe(catchError(this.handleApiError.handleError<any>("selecao-itinerario/itinerarios")));
}
```

**Frontend — `selecao-itinerario.component.ts`:**

```typescript
// antes (linha 75)
componentes: this.itinerarioService.getItinerarios(request),

// depois
componentes: this.selecaoItinerarioService.getItinerarios(request),
```

### Complementar — ativar guard de rota

O `canActivate` está comentado no routing module. Deve ser ativado com a funcionalidade 427:

```typescript
{
  path: path.ItinerarioFormativo.Selecao,
  component: SelecaoItinerarioComponent,
  canActivate: [IsLoggedGuard, IsAllowed],
  data: { roles: [permission.ItinerarioFormativoSelecao] } // 427
}
```
